# 万宝盒 · 时光模块 用户体验重设计 PRD

> 版本：v1.0  
> 日期：2026-04-21  
> 作者：高级产品经理视角  
> 范围：`:feature:lifetime` 模块（当前名"时光里程碑"）

---

## 1. 产品判断

### 1.1 用户 / 场景 / 问题

- **核心用户画像**：25-40 岁、对时间敏感、偶尔会产生存在主义焦虑或自我反思的都市用户。他们不一定每天打开，但会在某些情绪节点（生日、年末、深夜）想要"看看自己的人生进度"。
- **触发场景**：
  1. 深夜刷手机时的情绪消费——想看看"这辈子还能做多少次某事"。
  2. 生日/年末的自我盘点——需要一个有仪式感的数字总结。
  3. 朋友间分享"人生进度条"——社交货币。
  4. 设定个人目标后的正计时/倒计时——如"距离考研还有X天"。
- **当前替代方案**：生辰 App、时间规划局、手动备忘录、朋友圈发图。

### 1.2 真问题诊断

| 表面诉求 | 背后真实诉求 |
|---------|------------|
| "我想看我已经活了多久" | "我想确认自己的存在感和时间的重量" |
| "我想算还能吃多少顿饭" | "我想用具体数字来倒逼自己珍惜当下" |
| "我想记录人生里程碑" | "我想给自己的人生赋予叙事感和仪式感" |
| "这个模块功能好多" | "我不知道这个模块到底是干嘛的，没有统一心智" |

**伪需求识别**：
- "过去"/"将来"双 Tab 切换展示同一批卡片的不同数据——用户并不关心"已吃多少顿"和"还能吃多少顿"的对比，他们只想看其中一个有冲击力的数字。
- 10 个固定通用里程碑（100天、1000天...）——对用户个人毫无情感连接，看一次就忘。
- 人生进度条显示"已完成 X%"——心理负担重，且没有正向激励。

### 1.3 是否值得做 / 现在做 / 在万宝盒里做

- **与现有功能关系**：万宝盒内无直接重叠模块。AI 对话模块可提供"人生洞察"内容，但当前无联动。图像工具可提供"分享卡片生成"能力，但当前无调用。
- **优先级**：P1。理由：模块已存在且有一定工程基础，但当前体验不及格，用户留存低。重做后可成为万宝盒的"情感锚点"之一——一个让用户愿意记住并偶尔回来的模块。
- **成功标准**：用户首次设置完成后，7 日内回访率 > 15%；分享功能上线后，分享卡片月生成量 > 1000 张（万宝盒体量内合理目标）。

## 2. 范围界定

### 2.1 这次必须做（MVP）

1. 产品定位重塑 + 模块更名
2. 首次使用引导流程（出生日期设置）
3. 主页面信息架构重排（去掉 Tab，改为单页纵向分区）
4. 时间展示卡片重设计（从轮播改为静态震撼展示）
5. 人生进度卡片重设计（从"已完成%"改为"剩余%"或隐藏）
6. 频率事件卡片保留但简化（去掉"过去/将来"双态，默认展示"已完成"，长按/菜单切换"待完成"）
7. 里程碑系统改为"个人里程碑"（支持用户自定义，删除固定 10 个通用里程碑）
8. 空状态与错误状态全量设计
9. 文案全量重写

### 2.2 这次不做（明确划界）

- 社交功能（好友对比、排行榜）——超出当前模块边界，且万宝盒无社交基建
- AI 生成人生洞察（如"这辈子还能看 400 部电影"）——P1 可接 AIPromptExecutor 快速实现，但 MVP 先不做
- 桌面小组件（Widget）——独立技术方案，需另排期
- 数据导出/备份——低频需求，后续再说
- 深色模式专属视觉——复用现有 Glass 体系自动适配即可

### 2.3 后续可演进方向

- 接入 `AIPromptExecutor` 生成每日一句"人生洞察"
- 分享卡片生成（调用图像工具模块的卡片合成能力）
- 桌面小组件 + 实时秒级更新
- 一次性事件/纪念日/倒计时类型扩展

## 3. 信息架构重设计

### 3.1 新定位与名称

- **新名称**：**「时光沙漏」**（备选：「时光频率」、「时间手账」）
  - Why："沙漏"是时间流逝的强视觉符号，比"里程碑"更轻盈、更有诗意；"时光"保留了原有情感基调。
- **一句话定位**："记录你的时光频率，让每一秒都有重量。"
- **心智模型**：不是"计算器"，而是"个人时间纪念碑"——用户来这里是为了获得一种"时间的仪式感"，而不是为了精确计算。

## 4. 核心交互流程

### 4.1 主页面交互

| 元素 | 交互 | 反馈 |
|-----|------|------|
| 主时间卡片 | 点击 | 切换展示维度：年/天 → 时/分/秒（带动画过渡） |
| 主时间卡片 | 长按 | 弹出"复制数字" / "生成分享卡片"（P1） |
| 人生进度卡片 | 点击标题栏 | 展开/折叠（默认展开，用户可折叠） |
| 个人里程碑 | 横向滚动 | 惯性滚动，边缘渐隐 |
| 个人里程碑卡片 | 点击 | 进入详情页（显示达成日期、进度、备注） |
| 个人里程碑卡片 | 长按 | 编辑/删除 |
| 频率事件卡片 | 点击 | 卡片翻转动画：正面"已完成" → 背面"待完成" |
| 频率事件卡片 | 长按 | 进入编辑模式（显示删除按钮） |
| 底部"+"按钮 | 点击 | 弹出 BottomSheet：选择"添加频率事件" / "添加个人里程碑" |

### 4.2 首次使用引导

**核心原则**：不允许用户看到错误数据。当前代码用 `1990-01-01` 作为默认值是严重产品缺陷。

1. **欢迎页**：
   - 文案："时间从不等人，但你可以记住它。"
   - 副文案："设置你的出生日期，开启个人时光沙漏。"
   - 按钮："开始"（主按钮，不可跳过）
   - 背景：subtle 的粒子/星光动画，不喧宾夺主

2. **出生日期选择**：
   - 使用现有 `ChineseDatePickerDialog`
   - 最大日期限制为今天
   - 不预设任何日期，用户必须选择

3. **目标寿命（可选）**：
   - 文案："你期望的人生长度是？"
   - 默认 80 岁（比当前 100 岁更贴近现实，减轻心理负担）
   - 提供"跳过，使用默认"按钮

4. **事件推荐**：
   - 首次进入主页面后，底部弹出半屏推荐：
   - "为你推荐以下时光频率：吃饭、睡觉、春节、看书"
   - 用户可一键"全部添加"或"自定义选择"

### 4.3 编辑与管理

**编辑模式统一策略**：
- 当前右上角"编辑"图标点击后全局进入编辑模式，所有卡片显示删除按钮——这会导致误触。
- **建议改为**：长按单个卡片进入该卡片的编辑态，或点击卡片进入详情页后编辑。
- 全局编辑模式仅用于"批量管理"场景，入口放在右上角菜单 → "管理事件"。

**删除确认**：
- 所有删除操作（事件、里程碑）统一使用底部确认弹窗：
  - 标题："删除「吃饭」？"
  - 内容："相关统计数据将被清除，此操作不可撤销。"
  - 按钮："取消" / "删除"（红色）

## 5. 功能增强建议

### 5.1 保留功能（改造后）

| 功能 | 改造方式 | 优先级 |
|-----|---------|--------|
| 实时时间计算 | 保留秒级更新，但展示方式改为静态大卡片 | P0 |
| 频率事件 | 保留，但去掉"过去/将来"双态，改为单卡片可翻转 | P0 |
| 预设事件库 | 保留，但推荐策略优化（首次引导推荐 4 个） | P0 |
| 出生日期设置 | 保留，但改为首次强制设置，不设默认值 | P0 |
| 目标寿命设置 | 保留，默认值改为 80 岁 | P0 |

### 5.2 删除/弱化功能

| 功能 | 处理方式 | 理由 |
|-----|---------|------|
| "过去"/"将来"双 Tab | **删除** | 割裂体验，同一卡片展示两种数据造成认知混乱 |
| 固定 10 个通用里程碑 | **删除** | 对用户个人无意义，无法产生情感连接 |
| 人生进度条"已完成 X%" | **弱化** | 心理负担重，改为"已走过"视角或默认折叠 |
| 时间轮播（HorizontalPager） | **删除** | 自动轮播打断用户阅读，且 4 秒间隔让人焦躁 |

### 5.3 新增功能

| 功能 | 用户价值 | 实现方向 | 优先级 |
|-----|---------|---------|--------|
| **个人里程碑** | 用户可定义对自己有意义的时间节点（毕业1000天、30岁生日、恋爱周年） | 扩展 Room 表，支持名称、目标日期/天数、备注、图标 | P0 |
| **分享卡片生成** | 满足社交分享需求，为万宝盒带来自然流量 | 调用图像合成能力，生成 9:16 卡片（主数字 + 文案 + 水印） | P1 |
| **每日一句洞察** | 让数字有温度，提供情绪价值 | 接入 `AIPromptExecutor`，基于用户数据生成个性化文案 | P1 |
| **一次性事件/倒计时** | 用户需要"距离考研还有 X 天"这类正计时/倒计时 | 扩展事件类型：`ONE_TIME` 已存在但 UI 未充分利用 | P1 |
| **里程碑详情页** | 查看里程碑的历史进度、添加个人备注 | 新增子页面，展示时间线 | P2 |
| **数据重置** | 用户想重新开始 | 设置页增加"清除所有数据"，带二次确认 | P2 |

## 6. 状态设计

### 6.1 首次进入（无出生日期）

- **状态**：全屏欢迎页
- **文案**："时间从不等人，但你可以记住它。"
- **操作**："开始"按钮 → 进入出生日期设置

### 6.2 主页面空状态

**频率事件为空**：
- 文案："还没有时光频率"
- 副文案："添加你关心的事情，比如吃饭、看书、旅行..."
- 操作："添加第一个事件"按钮

**个人里程碑为空**：
- 文案："还没有个人里程碑"
- 副文案："毕业 1000 天、30 岁生日... 记录属于你的重要时刻"
- 操作："添加里程碑"按钮

### 6.3 加载态

- 当前文案"加载中..."过于生硬。
- **建议**："正在计算你的时光..."（配合 subtle 动画）

### 6.4 错误态

**出生日期解析失败**：
- 文案："日期数据出了点问题"
- 操作："重新设置"按钮

**数据库读取失败**：
- 文案："暂时无法读取事件数据"
- 操作："重试"按钮

### 6.5 离线态

- 本模块数据全部本地存储（DataStore + Room），**理论上不存在离线问题**。
- 但需考虑首次引导时用户拒绝存储权限的边界（Android 11+ 已弱化此问题）。

## 7. 情感化设计策略

### 7.1 核心原则

**让数字有温度，让时间有故事。**

### 7.2 具体策略

1. **文案人话化**：
   - 当前："人生进度"、"已度过的时光"
   - 改为："你已走过的旅程"、"剩下的时光"、"你的时光频率"

2. **洞察化表达（P1 接入 AI）**：
   - "如果每周看 1 部电影，这辈子还能看大约 2700 部"
   - "你已经度过了 10200 个清晨，还有约 18000 个清晨在等你"
   - "按照当前频率，你这辈子大约能吃 85000 顿饭"

3. **里程碑仪式感**：
   - 达成里程碑时，全屏 confetti 动画 + 文案："恭喜，你迎来了「毕业 1000 天」"
   - 里程碑卡片上显示"还有 X 天到达"或"已于 YYYY-MM-DD 达成"

4. **视觉温度**：
   - 主时间卡片使用 Glass 体系的半透明质感，背景 subtle 渐变
   - 不同时间段（清晨/午后/深夜）主卡片色调微变（清晨暖黄、深夜深蓝）
   - 频率事件卡片使用柔和的分段色，避免高饱和

5. **正向激励替代焦虑**：
   - 删除"已完成 X%"的表述
   - 改为"还有 X 年 Y 天，足够做很多事"
   - 进度条颜色从"警告色"改为"希望色"（如从红色/橙色改为蓝色/绿色渐变）

## 8. 数据可视化建议

### 8.1 主时间卡片

**当前问题**：HorizontalPager 轮播 6 个时间维度，用户无法一眼获取完整信息。

**建议方案**：
- 静态卡片，默认展示**最大的两个维度**（年 + 天）
- 超大字号（displayLarge），居中，字重 ExtraBold
- 点击卡片后，使用**数字滚动动画**切换为"时 + 分 + 秒"
- 背景：GlassCard + subtle 动态粒子（代表时间流逝）

```
┌─────────────────────────┐
│                         │
│        28 年            │  ← displayLarge, 主色
│        156 天           │
│                         │
│    已走过的人生          │  ← labelSmall, onSurfaceVariant
│                         │
└─────────────────────────┘
```

### 8.2 人生进度

**当前问题**：LinearProgressIndicator + "已完成 X%"，心理负担重。

**建议方案**：
- 保留进度条，但改为**"已走过"视角**
- 文案："人生旅程已走过 35%，预计还有 52 年"
- 进度条颜色：从浅到深的渐变（如浅蓝 → 深蓝），代表时间的深度
- 默认展开，用户可点击标题折叠
- **提供隐藏选项**：设置中可关闭人生进度显示（照顾敏感用户）

### 8.3 个人里程碑

**当前问题**：10 个固定里程碑，纵向列表，占用大量空间。

**建议方案**：
- 横向滚动卡片（类似 Story 样式）
- 每个卡片：圆形进度环 + 里程碑名称 + 状态（"还有 23 天" / "已达成"）
- 用户可自定义颜色和图标
- 达成后卡片有 subtle 金色描边或徽章标记

```
┌─────────────────────────────────────────┐
│  个人里程碑                    [管理 >]  │
├─────────────────────────────────────────┤
│  ┌─────┐  ┌─────┐  ┌─────┐  ┌─────┐   │
│  │ ◠◡  │  │ ◠◠  │  │ ◡◡  │  │  +  │   │
```

### 8.4 频率事件网格

## 12. 风险与取舍

### 12.1 主要风险

| 风险 | 影响 | 取舍方案 |
|-----|------|---------|
| 删除"过去/将来"Tab 后，老用户不习惯 | 中 | 在更新日志中说明，提供 1 个版本过渡期；频率事件卡片翻转即保留双态查看能力 |
| 个人里程碑需要新增 Room 表 + Migration | 中 | 使用 Room 自动 Migration，测试覆盖 |
| 强制设置出生日期提高进入门槛 | 低 | 仅需设置一次，且是核心功能的前提；提供清晰的"为什么需要"说明 |
| 分享卡片生成依赖图像工具模块 | 低 | P1 再做，MVP 不依赖；或先使用系统分享（纯文本） |
| "人生进度"隐藏/弱化引发争议 | 低 | 设置中提供开关，让用户自主选择是否显示 |

### 12.2 工程注意

- `LifeTimeCalculator.calculateMilestones()` 当前返回固定 10 个里程碑，删除后需同步清理 `MilestoneCheck` 的使用。
- `FrequencyEvent` 的 `ONE_TIME` 类型当前在 UI 中未充分利用，P1 可扩展为"一次性事件/倒计时"。
- `LifeTimeComponent` 中的 `LifeTimeTab` 枚举可废弃，但建议保留 1 个版本后删除，避免状态序列化兼容问题。
